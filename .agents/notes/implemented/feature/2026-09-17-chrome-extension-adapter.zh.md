# Agent Note: Chrome 扩展适配

Status: implemented

[English](2026-09-17-chrome-extension-adapter.md) | 中文

## Problem

桌面像素与焦点控制使简单的浏览器任务依赖 macOS 隐私授权、窗口尺寸和标签焦点。浏览器任务需要结构化网页控件和可见的用户授权机制。

## Decision

桌面宿主在全能 preset 中启用 `browser-extension` MCP 行。该行使用内置 Node 进程以扩展模式启动精确安装版本的 Playwright MCP。Chrome 管理安装和连接授权；应用不提取扩展令牌，也不自动批准连接。原生菜单会先显示说明，再打开官方商店。浏览器控制技能针对 Chrome 网页优先选择浏览器工具，并将 macOS 权限检查限定于桌面操作。

## Alternatives considered

**自行构建 Chrome 调试桥接。** 本次集成不采用，因为已有持续维护的扩展负责网页快照、引用校验、连接授权和重连。DS 适配固定依赖版本并提供白名单，不开放任意执行脚本或上传本地文件的工具。

**按需下载工具。** 不采用，因为任务启动会依赖包仓库可用性和变化的版本。

## Consequences

浏览器连接属于长期存在的 preset，因此同一 preset 的会话共享活动标签页；不支持同时进行浏览器控制任务。Chrome 扩展授权独立于 DS 文件权限。连接失败会停止，不回退到绕过浏览器授权的脚本。上游扩展需要独立安装，并保留自身的界面语言。扩展的本机传输独立于不监听端口的桌面应用协议。

Loader 测试启动真实固定版本 MCP 程序，验证工具发现、白名单、CLI 默认不启用和卸载清理。录制会话验证浏览器与桌面指令的交付。真实 Chrome 授权和表单操作仍需人工验收，工具发现不能证明这些步骤成功。

浏览器配置显式启用 stdio 进程在调用超时或取消后的替换。Playwright 可能在 MCP 取消后保留未完成的连接 promise；替换所拥有的进程会清除该 promise，不修改扩展，也不使用其免确认令牌。监督器等待传输关闭，共享并发清理，刷新工具，不重放中断操作。普通工具错误保留连接。真实 Loader／子进程 fixture（测试前置数据）忽略取消请求，验证新进程身份、恢复、不重放与清理；这不能解释 Chrome 授权页未出现的原因。
