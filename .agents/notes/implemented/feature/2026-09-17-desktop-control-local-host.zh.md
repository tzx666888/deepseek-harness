# Agent Note: 桌面控制使用本机进程

Status: implemented

[English](2026-09-17-desktop-control-local-host.md) | 中文

## 问题

Peekaboo 会自动发现正在运行的桥接进程。该进程拥有独立的 macOS 隐私授权：未获授权的桥接进程可能报告 Chrome 没有窗口，而本机可执行文件能正常看到窗口。反复截图和激活应用因而无法确定目标。

## 决定

个性化桌面预设使用 `--no-remote` 启动 Peekaboo MCP，让权限检查、窗口发现、观察和操作都在同一本机进程中进行。browser-control 技能要求模型选择已观察到的窗口 ID、聚焦窗口、读取控件、使用绑定快照的元素 ID，并验证结果。两次失败后只允许根据新观察恢复一次，随后停止，不改用临时编写的 Shell 自动化。

## 考虑过的替代方案

**保留自动桥接发现。** 未采用，因为其他应用的隐私授权状态会继续决定当前安装能否观察和控制窗口。

**以截图和 AppleScript 为主要操作方式。** 未采用，因为已观察到的失败不断改变焦点并混淆截图像素与输入坐标，而已有 MCP 工具提供窗口和元素选择器。

## 影响

本机应用仍需要 macOS 屏幕录制与辅助功能授权。此预设不使用远程桥接进程。重试规则是面向模型的指令，并非执行层硬限制。配置回归测试固定本机执行参数，会话记录回放验证浏览器控制指令的交付。仍需真实桌面验证，因为 CI 无法授予 macOS 权限或复现用户窗口。
