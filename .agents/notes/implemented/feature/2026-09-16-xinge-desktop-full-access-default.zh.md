# Agent Note: 鑫哥专属桌面端默认完全权限

Status: implemented

[English](2026-09-16-xinge-desktop-full-access-default.md) | 中文

## 问题

鑫哥专属桌面端继承了通用产品的默认权限：工作区内可写，扩大操作范围时逐次审批。该安装由业主作为可信本地执行端使用，期望一次明确的产品选择覆盖后续工作，因此重复出现的单次授权卡片会打断正常的仓库任务。

macOS 隐私控制独立于 Harness 权限预设。即使 Harness 内部启用了完全权限，当 macOS 拒绝应用访问桌面、文稿、下载或其他受保护资源时，应用仍然无法访问这些位置。

## 决策

鑫哥专属桌面端覆盖层把沙箱策略设为 `danger-full-access`，把审批策略设为 `never`，并把默认权限预设设为 `danger-full-access`。新会话不再经过 Harness 文件沙箱，也不会逐条请求命令审批。输入框仍保留权限选择器，必要时可把单个会话降为工作区内修改或仅可查看。

应用不会绕过或修改 macOS 隐私控制。业主仍需在系统设置中为已安装的应用授予受保护文件夹访问权或完全磁盘访问权限，操作系统继续是这些资源的最终授权方。个性化本地版本使用一个保存在仓库之外的固定本地代码签名身份，使 macOS 能在升级后继续把授权关联到同一个应用指定要求。

## 备选方案

**保留工作区内修改，并加入“始终允许此命令”。** 未采用，因为业主需要的是可信应用策略，而不是命令模式白名单。部分白名单仍会因新命令形式继续询问，也不等同于现有的完全权限预设。

**只关闭审批界面，不改变沙箱模式。** 未采用，因为工作区之外的命令仍会被拒绝，而且没有恢复路径。沙箱和审批必须通过现有权限预设一起改变。

**由应用自行授予 macOS 隐私权限。** 未采用，因为 macOS 要求用户本人批准涉及安全的隐私访问，应用代码不能静默给自己授权。

**每次构建继续使用临时签名。** 未采用，因为临时签名通过不断变化的代码哈希识别应用，macOS 隐私授权无法可靠地延续到后续替换版本。

## 结果

鑫哥专属桌面端的新会话默认获得 Harness 完全文件访问权限，不再显示逐条审批卡片。已有会话保留其已记录的权限，直到业主通过输入框权限选择器或 `/permission danger-full-access` 切换。macOS 仍可独立拒绝受保护目录；这类拒绝会被识别为系统隐私问题，而不是再次触发 Harness 审批。生成升级包还需要访问本地签名身份；其私钥和业主的 macOS 授权都不会进入仓库或发布压缩包。
